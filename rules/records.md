# 记录与任务

所有事项、通知和复盘保存在 output/records/ 的对应子目录，派生清单保存在 output/reports/。不在仓库根目录另建 records/、state/ 或 reports/。

## 分类与关联

- 指定沟通：保留来源，跨会话围绕同一事项关联，不因会话不同重复建任务。
- 公司通知：记录发布者、适用范围、生效时间、要求与相关事项；未明确适用于用户时标记待确认。
- 任务进展：区分提交、收到、审核、确认、最终交付，不把其中一步直接写成全部完成。
- 探索与补充：想法、尝试、问题先记录为探索；分析建议不自动转成正式要求。

新事项使用稳定递增 ID（例如 W0001），分配前检查已有 ID；通知可使用 N0001。单写入者维护，出现并发冲突先核对。名称改变不改变 ID。

事项文件的当前状态是权威记录。报告是派生视图，不作为另一份可独立修改的账本。根 LOG 只记录不含具体业务内容的维护或运行日志，不写会话、业务范围、结论或具体任务入口；事项内 LOG 保留具体变化。

## 状态与证据

任务状态：待行动、待回复、等别人、待确认、已完成、已取消。探索和通知不强制套用任务状态。

任务保存：稳定 ID、事项、状态、责任人、首次发现时间、最后证据、来源消息 ID 与链接、期限、建议下一步。无明确期限写“无明确期限”；责任人不明写“待确认”，不默认归给用户。

- 不因对方最后发言就判定需要回复；“好的”“收到”不等于完成。
- 只有明确完成证据或用户确认才能关闭。记录不完整时写“未见明确回复／需确认”，不直接认定漏回。
- 已完成、已取消事项保留，不因旧消息、转发或重复导入重新打开。新的矛盾证据先标记待核对，保持原关闭状态，等用户确认。
- 用户取消的事项不再提醒或执行；长期未提及不代表取消或完成。
- 久远且不确定的事项标注证据时间和不确定性，不冒充紧急任务。
- 正式要求、用户反馈和分析建议分别记录。用户更正优先更新当前理解，保留此前口径和更正依据。
- 新要求替代旧要求时，记录变更时间、来源和影响；不要抹掉原要求。

## LOG 写法

时间采用 `YYYY-MM-DD HH:mm +08:00`。每条一个主题，通常 2—4 个短条目，只写有内容的字段，不填空话。

```markdown
## YYYY-MM-DD HH:mm +08:00 — 事项变化

- 变化：发生了什么，已有何种证据。
- 确认／待确认：当前口径与缺口。
- 下一步：建议用户做什么；没有则省略。
- 来源：消息链接或标识；关联事项文件。
```

根 LOG 不记录具体任务内容或成果入口，也不复制聊天和任务清单。正文保留足够背景；引用只取必要内容，明确发送者和时间，不把转述当作直接承诺。

## 完整原文归档

用户要求按话题保存完整上下文时，遵循以下可复用流程；每次任务的具体范围只写入 output/。

1. 在 `output/records/tasks/<任务ID>/archive.md` 记录本次用户需求、授权来源、起止时间、备份及补采范围、文档结构和完整性要求。后续变化随任务记录更新，不加入通用规则或 skill。
2. scripts/sync.py 定位指定名称、完整分页采集到固定截止时间，并按每批最多 100 条导出。阅读全部范围内消息，关键词仅辅助定位，不代替上下文阅读。
3. 原群优先，备份用于核对和补缺；不把转发时间当成原始讨论时间。需要时用 scripts/reconcile_backup.py 解析合并转发，核对条数、原发送者和原时间；无内层 ID 时标明文本核对，不能声称 ID 级去重，不自动删除疑似重复记录。
4. 以实际备份终点确定补采缺口，不把某次任务的日期、条数或截止时间固化成后续任务默认值。无法读取的历史、回复、附件或撤回内容明确列出，不擅自替代来源。
5. 在 output/state/ 维护本次话题索引。每条已读消息归入话题或注明排除理由，跨话题可重复引用；保留提问、回应、变更与确认的完整原文和来源。
6. 各话题整理写入 output/records/topics/，区分背景、已确认要求、方案讨论、进展、口径变化和待确认；原文与分析分开，不补造责任、期限或实现结果。
7. scripts/build_document.py 从索引直接取已采集原文，生成 output/reports/ 下的文档。按话题保留原文，再独立整理章节；按需附跨话题进展、原附件全文与排除依据。生成器负责拼装和校验，语义判断由 AI 完成。
8. 核对消息覆盖、分页、正文、回复、备份、附件和引用；全部分类不等于所有内容可恢复。完成保存前不清理 pending，分析期间有变化的消息继续保留。

### 内部话题索引

索引由 AI 基于实际消息维护，用户不需要手动填写。字段约定如下，不预填任何真实任务内容：

| 字段 | 含义 |
|---|---|
| title | 本次归档标题 |
| chats | 本次授权来源在本地配置中的名称 |
| start / end | 本次归档起止时间，带时区 |
| topics | 话题数组；每项含 title、message_ids 和 summary（本地整理文件路径） |
| excluded | 消息 ID 到排除理由的映射 |
| output | output/reports/ 下的目标文档路径 |
| intro / review | 可选，output/ 下的采集说明与跨话题整理文件路径 |
| resource_index | 可选，output/ 下的已下载资源索引路径 |
| include_attachments | 是否附上原 Markdown 附件全文与截图 |

原文不经 AI 二次抄写。不存在的消息、缺少时间覆盖、未分类消息或空的整理章节均停止生成；具体索引、说明、状态和成果仅保存在 output/。
